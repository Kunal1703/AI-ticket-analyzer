## Architecture in one screen

FastAPI **app factory** (`create_app`) owns resources on `app.state`, injects them via `Depends` (`app/dependencies.py`), disposes them in `lifespan`. Every external system is behind an **abstraction + registry/factory**: AI provider (`app/ai/`), cache (`app/cache/`), auth (`app/auth/`), tenancy (`app/tenancy/`), DB via ports + SQLAlchemy stores (`app/db/`). Business logic depends on abstractions and provider‑agnostic **error hierarchies**, never on SDKs. Optional subsystems **degrade gracefully**. See [01_architecture.md](01_architecture.md).

- Add an agentic action type → add an `ActionType` + an `ActionHandler` (+ the `DESTRUCTIVE_ACTIONS` set if outward‑facing) and register it in `build_action_handlers`; the state machine, approval gate, and audit trail apply automatically ([25_actions.md](25_actions.md)).
- Add an action suggester → new `ActionSuggester` impl + a `build_action_suggester` branch; it only *proposes* (approval/execution unchanged) ([25_actions.md](25_actions.md)).
- Full recipes: [developer_guide.md](developer_guide.md).

## Things that must NEVER be rewritten (see D‑list in [12_design_decisions.md](12_design_decisions.md))

- `Provider*` exception hierarchy + translation; route catches only `Provider*`.
- Error envelope `{"error":{code,message,request_id,details?}}` with **stable** code slugs.
- `Cache` protocol + best‑effort semantics; `sha256(strip().lower())` key.
- Best‑effort persistence (never breaks `/analyze`).
- App‑factory/`lifespan` ownership; no import‑time stateful singletons.
- Auth identity‑vs‑session split; `get_current_user` catches `AuthError` **and** `TokenError`.
- API keys hashed (SHA‑256), plaintext once, revocable; passwords Argon2.
- Nullable `organization_id` (tickets/analyses); `usage_events.organization_id` NOT NULL; one‑driver PG; never edit shipped migrations.
- Best‑effort metering (own session, cache‑miss only); quota gate before the LLM call (402); legacy `/analyze` unmetered/unlimited.
- Stripe SDK behind `BillingProvider` (lazy import); inbound webhooks idempotent + signature‑verified (bad signature → 400).
- Batch reuses `run_analysis` behind the `JobRunner` (no second analyze path); background‑visible stores are sessionmaker‑backed.
- Outbound webhooks signed (HMAC) + best‑effort (never break the batch); httpx client injected, behind the `WebhookDispatcher` port.
- `/health` no‑deps; `/ready` no‑LLM. Legacy `/analyze` contract.
- `OPENAI_*` env aliases (back‑compat); tests use canonical `llm_*` kwargs.
- RAG: every vector tenant‑scoped (no cross‑org leakage); embeddings provider‑agnostic (SDK behind the port) with a keyless offline default; analyze‑path retrieval best‑effort + tenant‑only; prompt `v2` append‑only (v1 context‑free); `analyze(context=…)` additive.
- Agentic actions: **human‑approved by default** (the state machine makes executing an unapproved action a 409); destructive types never auto‑execute; **every transition audited**; actions/audit tenant‑scoped and approval requires a **user** (never an API key); `suggest_actions` additive (default‑raise).

## How to continue development (workflow)

1. Confirm the milestone/scope with the user; implement **one** capability behind a clean abstraction.
2. Prefer extension points over rewrites. If you must change a "NEVER change" item, stop and get explicit sign‑off.
3. Keep it green at every step: `ruff` + `mypy` + `pytest` (run pytest **with and without `OPENAI_API_KEY`**).
4. Verify DB work **offline** (`alembic upgrade head --sql`) and with fakes/mocked sessions; add `skipif` integration tests.
5. Update the relevant `docs/project_continuation/*.md` if you change architecture.
6. Do **not** commit unless asked; when asked, make a scoped commit (stage only the intended files — the tree may carry unrelated uncommitted edits).
